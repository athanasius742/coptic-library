# Phase 1 — Book Chapter HTML Tag & Structure Inventory

> Generated by `apps/web/scripts/analyze-content-html.mjs` (a streaming, parser-based
> walk of every `content.xhtml`). Machine-readable data: `tag-inventory.json`.
> Re-run with: `node apps/web/scripts/analyze-content-html.mjs`

## Scope

- **Files scanned:** 27,914 `content.xhtml` (all under `books/st-takla.org/**/chapters/**`)
- **Files with a non-empty `<body>`:** 27,914 (100%)
- **Books (dirs containing a `chapters/`):** 348
- **Distinct tags:** 46
- **Parse:** htmlparser2 (real HTML parser, not regex); single streaming pass, ~4.6s total.

## Headline takeaways (for the renderer spec)

1. **Attributes are already almost entirely stripped.** Across the whole corpus the
   only attribute names that ever appear are: `alt, charset, colspan, dir, href, lang,
   rel, src, type, xml:lang, xmlns`. **There are zero `class`, `id`, `name`, or
   `style` attributes anywhere.** Structure detection must be **content- and
   tag-shape-based**, never class/id-based.
2. **`<a>` dominates** (1.6M) — most are inter-book links (`../../...`), plus heavy
   intra-page `#anchor` footnote/TOC links whose target `id`/`name` anchors **were
   stripped during cleaning** (see Anomalies -> broken anchors). The renderer must
   **reconstruct anchor ids** from the `#...` href values to make footnotes/TOC jump.
3. **Presentational soup is the bulk:** `font` (468k), `span` (499k), `b` (126k),
   `i` (95k), `u` (3k), `center` (35k) carry no semantics and should collapse to
   text / minimal emphasis.
4. **Headings are inconsistent:** `h1` (56k, every book), `h3` (25k), `h4`, `h6`,
   `h5`. Many are decorative leftovers (`<font><h3></h3></font>` empty shells, and a
   per-chapter source-TOC `<h1>` block). Page chrome already renders the chapter
   title as `h1`, so in-body headings should **demote** and empties should drop.
5. **`<table>` is overwhelmingly layout, not data:** of 10,875 tables, ~90% wrap a
   single `images/...` image (image cards), ~391 are "محتويات/Contents" TOC tables,
   and only ~718 are candidate data tables. Classify by content, not by tag.
6. **`<sup>` (21k) is NOT the footnote mechanism.** It almost always wraps the
   parentheses of inline scripture citations, e.g. `(لو24: 45)`. Footnote *markers*
   are bracketed text links: `<a href="#_ftnH1">[1]</a>` <-> back-link
   `<a href="#_ftnHref1">[1]</a>`.

### Document scaffold (strip before rendering body)

`html, head, meta, title, link, body` each appear exactly 27,914x (once per file) -
they are the per-file wrapper; the renderer extracts and renders only `<body>`
contents.

### Scraper-artifact / junk tags (strip, keep inner text)

`button` (71), `input` (20), `nav` (10), `form` (10), `button-hide` (5),
`o` (117, all in 1 book - Office-namespace `<o:p>` remnants), `area`/`map` (142/4 -
image-map leftovers), `dir` (9, deprecated). These are rare and noise.

## Distinct meaningful class / id values

**None.** No element in the corpus carries a `class`, `id`, `name`, or `style`
attribute. (The cleaning step that produced `content.xhtml` already removed them.)
Implication: every "special structure" below must be recognized **structurally**
(tag shape + text content + href shape), and the renderer must **synthesize** the
`id` anchors needed for in-page footnote/TOC navigation.

## Ranked candidate special structures

Ranked by impact (frequency x how much dedicated rendering helps).

### 1. Inter-page / intra-page anchors - `<a>` (1,596,350 occ; 348 books)
- Most `href`s are relative inter-book links (`../../...html`) -> port existing
  `resolveHref`/`rewriteToInternal` (internal route rewrite vs `target=_blank`).
- **Intra-page anchors:** 139,172 `<a href="#...">` across 227 books. Targets follow
  predictable schemes: `#_ftnH1` / `#_ftnHref1` (footnotes), and TOC `#...` slugs.
- Representative: `books/st-takla.org/adel-zekri/augustine-consentius-120/chapters/02-text/content.xhtml`
  - `<a href="#_ftnH1"><b>[1]</b></a>` (marker) and `<a href="#_ftnHref1">[1]</a>` (note).

### 2. Image-wrapper tables (9,766 tables; 329 books)
- `<table>` whose only payload is `<img src="images/...">` + caption + "Gallery" links.
  These are image *cards*; assets are not in-repo.
- Representative: `books/st-takla.org/anba-raphael/i-willingly-ate/chapters/07-liturgy/content.xhtml`
- **Decision input:** current pipeline strips `images/...` tables; keep stripping
  (or treat as a styled figure placeholder) - assets would need a fetch follow-up.

### 3. Footnote / scripture markers - `<sup>` + bracket links (21,351 `<sup>`; 156 books)
- `<sup>` wraps citation parentheses, e.g. `<sup>(</sup>لو 24: 45<sup>)</sup>` - a
  *scripture reference* convention, not a footnote ref.
- Actual footnotes = the `[n]` bracket-link pairs from #1.
- Representative: `books/st-takla.org/amir-nasr/alex-rome/chapters/03-mark/content.xhtml`

### 4. TOC tables - "محتويات / Contents" (391 tables; 58 books)
- `<table>` whose text starts with `محتويات` (or `Contents`), rows = `#anchor` links
  into the chapter (matching the stripped-id problem in Anomalies).
- Representative: `books/st-takla.org/amir-nasr/alex-rome/chapters/03-mark/content.xhtml`
  ("محتويات رسولية مارمرقس ... الحواشي والمراجع") and `.../04-marc/`, `.../05-opposition/`.
- -> styled, collapsible TOC component with working in-page anchors.

### 5. Data tables (718 tables; 99 books)
- Tables that are neither TOC nor image-wrapper - genuine tabular content
  (e.g. paragraph/section index tables: cols "فقرة | عنوان").
- Representative: `books/st-takla.org/adel-zekri/augustine-consentius-120/chapters/02-text/content.xhtml`
  and `books/st-takla.org/adel-zekri/augustine-faith/chapters/02-text/content.xhtml`.
- -> responsive styled `<table>` (with `colspan`/`rowspan` support - the only table
  attrs present).

### 6. Centered / poetry stanzas - `<center>` (35,328; 47 books) + multi-`<br>` `<p>` (639; 69 books)
- `<center>` is concentrated in a few books (notably church-books/dafnar hymnal,
  anba-raphael) -> likely hymn/verse centering.
- `<p>` with >=2 `<br>` is a *weak* poetry signal: it catches real stanzas but also
  Q&A lists and bulleted runs (false positives - see examples in JSON). Treat as a
  heuristic to refine, not a hard rule.
- Representative center: `books/st-takla.org/church-books/dafnar/chapters/01-Coptic-Defnar-01-Tout/content.xhtml`

### 7. Blockquote (3 occ; 3 books)
- Effectively absent. Real scripture/quote emphasis is done via `<b>`/`<center>`,
  not `<blockquote>`. Not worth a dedicated path beyond base styling.

### Strip-list confirmed by data
`script`/`iframe`/`style` never appear (already removed). Strip on render:
`button, input, form, nav, button-hide, o, area, map, link, meta` and any `on*`
handlers (none observed but sanitize anyway).

## Renderer-spec implications (summary)

- Parse `<body>` only; sanitize against the tiny real attr allowlist
  (`href, src, alt, colspan, rowspan, dir, lang`).
- Collapse presentational tags (`font/span/b/i/u/center`) to text + minimal emphasis.
- Demote/normalize headings; drop empty heading shells.
- Detect TOC vs image-wrapper vs data tables by **content**, not tag.
- **Reconstruct `id` anchors** from `#...` hrefs so footnotes/TOC navigate (15k files
  affected) - top priority.
- Keep stripping `images/...` (assets absent) unless an asset-fetch follow-up is taken.
- Port `resolveHref`/`rewriteToInternal` for the 1.6M `<a>` links.
